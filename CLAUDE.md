## Правило: current_state.md

Рядом лежит **`current_state.md`** — снимок текущего состояния (что сделано,
что в работе, следующий шаг). Он отделён от этого файла, чтобы CLAUDE.md
оставался про правила/архитектуру, а не про сиюминутный статус.

- **В начале новой сессии** — прочитай `current_state.md`, чтобы понять, на
  чём остановились.
- **После завершения задачи** — обнови `current_state.md`: что изменилось,
  какой следующий шаг. Не копи изменения "на потом".

## Стек — утверждено

**Вариант A: Vanilla JS + GitHub Pages.** Зафиксировано в ТЗ (раздел 3),
причина — тот же стек, что у `alias game` (единая экосистема, GitHub Pages
уже используется), нулевая стоимость хостинга, максимальный контроль.

- Frontend: чистые HTML/CSS/JS, без фреймворка и build-степа
- Анимации при скролле: CSS `animation-timeline: view()` (появления блоков) +
  GSAP ScrollTrigger только для сложных сцен (счётчики HSK3/HSK4, параллакс
  иероглифов в hero)
- Хостинг: GitHub Pages, автодеплой через GitHub Actions при пуше в main (как
  у `alias game`)
- Аналитика: Яндекс.Метрика
- Изображения: WebP, lazy loading; видео — не хранить в репозитории, только
  YouTube (unlisted) / Cloudflare Stream через iframe
- Отзывы: статический JSON в репозитории (не БД — меняются редко)

## Интеграция бронирования — backend уже существует

Бэкенд бронирования **не нужно писать заново** — он уже есть и работает в
соседнем проекте `../teacher-bot` (Railway, FastAPI, тот же аккаунт
TiemuLaoshi). Полная документация: `../teacher-bot/WEBSITE.md` и
`WEBSITE_SETUP.md`.

- **API** (`web/server.py` в teacher-bot):
  - `GET /api/slots?days=14` — расписание на N дней (часы НСК, `free: bool`)
  - `GET /api/my-lessons?name=...` — уроки ученика для режима "перенос"
  - `POST /api/book` — заявка (`mode: new|floating|regular`, name, date,
    hour, contact, comment, honeypot `website`); при успехе учителю приходит
    карточка в Telegram с кнопками Подтвердить/Отклонить
- Время в API — НСК; фронтенд обязан конвертировать в МСК (сдвиг −4 часа,
  см. `mskHour()` в существующем `teacher-bot/web/static/app.js` — логику
  можно скопировать)
- **CORS не настроен** на `teacher-bot/web/server.py` — сейчас сайт бронирования
  раздаётся same-origin. Для запросов с домена GitHub Pages нужно добавить
  `CORSMiddleware` с разрешённым origin(ами) сайта-визитки — это правка в
  `teacher-bot`, не в этом репозитории.
- В `teacher-bot/schedule_website/` уже есть отдельный полностью рабочий сайт
  записи (тема "Крем": `--bg:#F2EADF`, `--accent:#13351D`) — это **референс
  реализации виджета**, а не то, что нужно встраивать iframe'ом: блок
  "Бронирование" в макете этого лендинга (`id="booking"`) стилизован под
  дизайн-систему лендинга, значит виджет здесь верстается заново под этот
  стиль, но дергает те же три эндпоинта.
- Rate-limit на бэкенде: 8 заявок/час с IP — не нужно дублировать на фронте,
  просто корректно показывать ошибку из `resp.detail`.

## Как работать с макетом (`Design_Mockup/*.html`)

Файлы — самораспаковывающиеся бандлы (~9 МБ), исходная разметка лежит JSON-строкой
в `<script type="__bundler/template">`. Извлекать скриптом, не читать файл целиком:

```js
const fs = require('fs');
const html = fs.readFileSync('Design_Mockup/Сайт Тимура.html', 'utf8');
const m = html.match(/<script type="__bundler\/template">([\s\S]*?)<\/script>/);
const template = JSON.parse(m[1]);
fs.writeFileSync('scratch/template.html', template); // писать во временную папку, не в репозиторий
```

Затем работать с `template.html` (грепать по разделам, копировать инлайн-стили).
Изображения в макете подставлены как `<img src="UUID">` — сами файлы не
экспортированы, для реального сайта нужны исходники (`myphoto.jpg`,
скриншоты, HSK-сертификаты) или заглушки.

Полезно: из 3229 строк `template.html` первые ~2898 — это `@font-face`
Google Fonts. **Реальная разметка — строки 2899-3229** (~330 строк), её можно
и нужно читать целиком: `sed -n '2899,3229p' template.html > markup.html`.
Там же в конце лежит `<script type="text/x-dc">` с данными макета —
в том числе 7 текстов отзывов с именами и датами (готовое сырьё для
`assets/reviews.json`) и логика демо-виджета бронирования.

### Эталон `fullpage.png` отрендерен при ширине 909px

Проверено: `fullpage.png` — **909×5916**, то есть это рендер при узком
viewport, а не десктоп 1440. Заголовок Hero в нём переносится на 6 строк,
бренд в хедере — на 2 строки. **Сверяться нужно, рендеря свою страницу при
`--width 909`**, иначе сравнение бессмысленно.

**В макете нет ни одного `@media`** (проверено грепом по всему бандлу) —
фиксированные grid-колонки и `max-width:1240px`. Значит эталона мобильной
версии не существует: адаптив (точки перелома, порядок колонок в стопке,
размеры шрифтов) — наше проектное решение, сверять его не с чем.
Десктопный вид при 1440px тоже не покрыт эталоном — контейнер там просто
раскрывается до 1240px.

`#C19A3E` и `#E3C36C` (золото) тоже встречаются в макете, но их нет в

## Правила работы

1. **Следуй `Design_Mockup/screenshot_skill.md` дословно** для каждого блока,
   у которого есть макет: сверстать → скриншот → сравнить с `fullpage.png`
   (спейсинг, шрифты, цвета, радиусы, тени) → править → пересравнить, минимум
   2 раунда. Не "улучшай" макет и не добавляй элементы, которых там нет.
2. **Не выдумывай контент.** Тексты по блокам 1-3, 4 (методика), 6
   (результаты), 8 (цены), 10 (CTA) уже заданы дословно в
   `ТЗ_сайт_учителя_китайского.md` (раздел 2) — использовать как есть, не
   перефразировать.
3. **Блок "Бронирование"** — не выдумывай новый бэкенд. Смотри
   `../teacher-bot/WEBSITE.md` за контрактом API, копируй логику конвертации
   времени НСК→МСК из существующего `app.js`, а не изобретай заново.
4. **Видео с учениками (блок "Технологии")** — перед публикацией нужно
   письменное/переписочное согласие; если на видео несовершеннолетние —
   согласие родителей и без крупных планов лица/имени (см. ТЗ, раздел 5).
5. **Не создавай Supabase/платные интеграции "про запас"** — их тут не будет,
   весь стек — статика + существующий Railway-бэкенд teacher-bot.
