Лендинг-визитка репетитора китайского языка. Задача сайта — конвертировать
посетителя в заявку на пробный урок.

Это живой документ — обновляй его по ходу работы: закрывай открытые вопросы,
добавляй новые решения, убирай то, что устарело.

## Правило: current_state.md

Рядом лежит **`current_state.md`** — снимок текущего состояния (что сделано,
что в работе, следующий шаг). Он отделён от этого файла, чтобы CLAUDE.md
оставался про правила/архитектуру, а не про сиюминутный статус.

- **В начале новой сессии** — прочитай `current_state.md`, чтобы понять, на
  чём остановились.
- **После завершения задачи** — обнови `current_state.md`: что изменилось,
  какой следующий шаг. Не копи изменения "на потом".

## Стек — утверждено

**Вариант A: Vanilla JS + GitHub Pages.** Зафиксировано в ТЗ (раздел 3),
причина — тот же стек, что у `alias game` (единая экосистема, GitHub Pages

- Frontend: чистые HTML/CSS/JS, без фреймворка и build-степа
- Анимации при скролле: CSS `animation-timeline: view()` (появления блоков) +
  GSAP ScrollTrigger только для сложных сцен (счётчики HSK3/HSK4, параллакс
  иероглифов в hero)
- Хостинг: GitHub Pages, автодеплой через GitHub Actions при пуше в main (как

- Аналитика: Яндекс.Метрика
- Изображения: WebP, lazy loading; видео — не хранить в репозитории, только
  YouTube (unlisted) / Cloudflare Stream через iframe
- Отзывы: статика в репозитории (не БД — меняются редко). Изначально
  планировался `assets/reviews.json`, по факту тексты лежат в `index.html` —

## Как работать с макетом (`Design_Mockup/*.html`)

Файлы — самораспаковывающиеся бандлы (~9 МБ), исходная разметка лежит JSON-строкой
в `<script type="__bundler/template">`. Извлекать скриптом, не читать файл целиком:

```js
const fs = require('fs');
const html = fs.readFileSync('Design_Mockup/Сайт Тимура.html', 'utf8');
const m = html.match(/<script type="__bundler\/template">([\s\S]*?)<\/script>/);
const template = JSON.parse(m[1]);
fs.writeFileSync('scratch/template.html', template); // писать во временную папку, не в репозиторий
```

Затем работать с `template.html` (грепать по разделам, копировать инлайн-стили).
Изображения в макете подставлены как `<img src="UUID">` — сами файлы не
экспортированы, для реального сайта нужны исходники (`myphoto.jpg`,
скриншоты, HSK-сертификаты) или заглушки.

Полезно: из 3229 строк `template.html` первые ~2898 — это `@font-face`
Google Fonts. **Реальная разметка — строки 2899-3229** (~330 строк), её можно
и нужно читать целиком: `sed -n '2899,3229p' template.html > markup.html`.
Там же в конце лежит `<script type="text/x-dc">` с данными макета —
в том числе 7 текстов отзывов с именами и датами (уже перенесены в
`index.html`, Этап 1.8) и логика демо-виджета бронирования.

### Эталон `fullpage.png` отрендерен при ширине 909px

Проверено: `fullpage.png` — **909×5916**, то есть это рендер при узком
viewport, а не десктоп 1440. Заголовок Hero в нём переносится на 6 строк,
бренд в хедере — на 2 строки. **Сверяться нужно, рендеря свою страницу при
`--width 909`**, иначе сравнение бессмысленно.

**В макете нет ни одного `@media`** (проверено грепом по всему бандлу) —
фиксированные grid-колонки и `max-width:1240px`. Значит эталона мобильной
версии не существует: адаптив (точки перелома, порядок колонок в стопке,
размеры шрифтов) — наше проектное решение, сверять его не с чем.
Десктопный вид при 1440px тоже не покрыт эталоном — контейнер там просто
раскрывается до 1240px.

### `fullpage.png` склеен из отдельных «экранов» — на стыках бывает брак

Эталон собран по-экранно (`data-screen-label`), и склейка местами врёт.
Проверено на блоке «Финальный CTA»: у него **срезаны верхние 54px**
(первая строка заголовка обрезана краем тёмной плашки — так не бывает при
нормальном потоке) и **всё центрованное содержимое сдвинуто на +7px вправо**
(экран отрендерен при ширине ~923px и обрезан до 909). Абсолютно
позиционированный `加油` (`left:40px`) при этом совпадает пиксель-в-пиксель —
значит смещён не растр, а центровка внутри него.

Как отличить брак эталона от своей ошибки:
1. Замерить ширину текстовой строки в обоих (`--row N --edges`). Если ширина
   совпала, а позиция нет — виноват эталон, а не твоя вёрстка.
2. Посчитать высоту блока из CSS макета вручную и сравнить с высотой тёмной
   полосы в эталоне. Разница ровно в высоту одного ряда — признак склейки.

Не подгонять вёрстку под такой брак. Считать эталоном исходный CSS из
`markup.html`, а `fullpage.png` — проверкой.

### Картинки макета зашиты в бандл — их можно достать

`<script type="__bundler/ext_resources">` в бандле **пустой** — не
обмануться. Настоящие ресурсы лежат картой `"UUID": {"mime", "data": base64}`
россыпью по файлу, а в разметке подставлены как `<img src="UUID">`.

```bash
node tools/extract-assets.js --save scratch/mockup-assets
```

Заявленный `mime` врёт (у картинок `image/jpeg`, а по сигнатуре WebP) —
формат определяется по магическим байтам. Всего в макете 3 картинки:

| UUID (начало) | Что это | Формат |
|---|---|---|
| `b7cad5cf` | Фото Тимура (Hero и «О преподавателе») | webp 809×1214 |
| `83800686` | Превью Alias-игры | jpg |
| `5f4f4484` | Скриншот личного кабинета | png |

⚠️ **`myphoto.jpg` — на самом деле WebP** с неверным расширением, и он
байт-в-байт совпадает с картинкой из макета. Лежит как
`assets/img/timur.webp`. Скорее всего `shuoshuoyouxuscreenshot.jpg` и
скриншот кабинета — тоже те же файлы, проверять `md5sum` перед тем, как

## Ловушки reset'а (проверено на Hero — сэкономит время на каждом блоке)

В макете **нет CSS-reset'а**, поэтому привычные «правильные» правила ломают
совпадение с эталоном. Три случая, найденных на Hero:

1. **`body { line-height: 1.5 }` — нельзя.** В макете базовый `line-height`
   не задан (`normal`), нужные значения проставлены поэлементно. С 1.5 шапка
   и колонка текста становятся выше, а отцентрованное по ним фото уезжает
   на 10px. Стоит `line-height: normal`.
2. **`.btn { text-align: center }` — нельзя.** У кнопок в макете выравнивание
   не задано, многострочный текст прижат влево («Записаться на» /
   «пробный урок»).
3. **`box-sizing: border-box` + `img { max-width: 100% }` ломают геометрию
   фото.** В макете `width:400px` — это картинка, рамка 6px идёт сверху
   (итого 412px), и фото не сжимается колонкой. Именно из этих 412px
   вытекает ширина текстовой колонки (345px) и переносы заголовка. В
   `.hero__photo` пришлось локально вернуть `box-sizing: content-box` и
   `max-width: none`.
4. **`box-sizing: border-box` на карточках и контейнерах меняет ширину**
   (найдено на «Отзывах» и «Бронировании»). Любой `width`/`max-width` в
   макете — это ширина **содержимого**, поля и рамка идут сверху. Карточка
   отзыва: `width:340px` + поля 26px + рамка = 394px; с border-box текстовая
   колонка уже на 54px, длинные отзывы получают лишнюю строку и **вся**
   лента вырастает на 23px (489 против 468). Контейнер виджета
   бронирования: `max-width:760px` + `padding:0 48px` = 856px наружу; с
   border-box карточка виджета на 96px уже эталона (расхождение 13%
   вместо 1.9%). Лечится `box-sizing: content-box` на этом элементе.
5. **`img { display: block }` сдвигает отцентрованное фото вверх** (найдено
   на «О преподавателе»). В макете `<img>` строчный, и обёртка получает
   «хвост» строки под базовой линией: не 420px, а ~426px. При
   `align-items:center` по соседней колонке разница делится пополам — фото
   встаёт на 3px выше, чем при `display:block`. Лечится локальным
   `display:inline` на самой картинке; высота ряда при этом не меняется,
   её задаёт текстовая колонка.

Общий вывод: если блок «почти совпал, но всё смещено» — искать не в
отступах блока, а в глобальных правилах, которых в макете нет.
